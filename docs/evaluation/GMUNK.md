# GMUNK: five-level, 20-criterion evaluation

Project-specific adaptation of a supplied reference; not an official rubric, endorsement or review by the named designer.

Supplied reference: **gmunk_design_hero.md**. SHA-256: dfddf4c08acf3e1ac5384129fa511493a7bd3879dbc08cc1d596b5e064351b56.

Apply cinematic/slide advice to real desktop utility, clarity, material fidelity, hierarchy and motion. Existing user elements and usability requirements take priority over film-specific prescriptions. No fictional data or decorative motion is required for points.

## Five levels

| Points | Anchor |
| --- | --- |
| 1 | Absent or contradicts the task. |
| 2 | Partially present, with a major visible or functional gap. |
| 3 | Usable on the main path, with clear consistency or coverage gaps. |
| 4 | Strong, verified for the main path; a bounded polish or validation gap remains. |
| 5 | The criterion acceptance is verified across relevant views/states with no known material gap. |

## Twenty criteria

| # | Criterion | Acceptance required for the top level |
| --- | --- | --- |
| 01 | Structural grid | Main groups share explicit axes and spacing tokens across player, playlist, transfer and settings views. |
| 02 | Primitive geometry | Existing Enochian circles, lines, caps and type form one consistent vocabulary. |
| 03 | Material authenticity | Original Enochian gradients, texture, glyphs and shadows match their source. |
| 04 | Depth and lighting | Control depth and pressed states retain consistent lighting and never obscure text. |
| 05 | Readable micro-typography | Control and data labels remain legible at the actual desktop/compact size. |
| 06 | Micro-geometric precision | Borders, baselines, hit regions and glyphs fit without clipping or off-by-one drift. |
| 07 | Structure before density | Information is grouped before detail is added; essential tasks are not crowded out. |
| 08 | Tangible real controls | Every visible control changes a real media/transfer value or performs the named action. |
| 09 | State visibility | Ready, playing, paused, downloading, complete and failed states are visually distinct and truthful. |
| 10 | Physical press feedback | Pointer and keyboard activation retain the original key travel and release behavior. |
| 11 | Live screen integration | Actual running views, not only static compositions, support the design claims. |
| 12 | Immediate response | Actions acknowledge promptly and longer work shows relevant progress. |
| 13 | Temporal continuity | Pause/resume/seek/window transitions retain context and avoid disruptive resets. |
| 14 | Palette discipline | Ivory and Obsidian preserve the existing base and signal roles. |
| 15 | Contrast under real conditions | Labels, focus and status are legible in both finishes without relying on color alone. |
| 16 | Every detail serves the task | Displayed details explain the current file, queue, transfer or next action. |
| 17 | Relatable physical metaphors | Transport, volume, seek, switches and utilities match familiar functions. |
| 18 | Cross-view composition | Player, playlist, cards, list and dialogs share a coherent visual structure. |
| 19 | Scale resilience | Normal/compact and supported narrow layouts retain readable, reachable controls. |
| 20 | Live responsiveness | Motion and rendering do not stall real playback, input or transfer interactions. |

## Gate

At least **95/100 on this lens**, no criterion below 4, and the shared mandatory workflow checks must pass. Use the same frozen evidence rules as [Ryo](RUBRIC.md). These are separate scores, not an average.
